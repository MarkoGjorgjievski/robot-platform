A: Tabs above DOM viewer

DOM/Screenshot/HTML tabs sit at the top of the main content area. DOM is default. Schema field highlights show inline (like the purple "product_name" badge). The DOM tree is the primary interaction surface.

B: Rendered page (iframe) + tabs below

Main area shows the actual rendered page in an iframe/sandbox. Tabs at the bottom switch between: Rendered, DOM Tree, Screenshot, HTML. Schema fields highlight directly on the rendered page with overlays. Closest to Chrome DevTools feel.

C: Split — Rendered + DOM side by side

Left half shows rendered page, right half shows DOM tree. Hover on either side highlights the corresponding element on the other. No tabs needed — both always visible. Like Chrome DevTools Elements panel.

Key considerations

  • A — DOM tree only, no rendered view. Simple, works well for selector-building. But you can't see what the page actually looks like.
  • B — Rendered page is primary. Best visual experience. But harder to pick selectors from rendered view alone.
  • C — Both visible, linked. Most powerful for selector building (see element + its selector simultaneously). But splits the space.
