# Email, with a local catcher — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The worker emails an organisation's owners and admins when a website turns to "Needs attention" or a run fails, and emails account messages (staff entering the organisation, a role change, a removal), over SMTP — a Mailpit container catches them locally and a real provider is a configuration change.

**Architecture:** `@robot/db` gains `users.email_attention`, `users.email_failed_runs`, `sources.attention_since` and an `email_messages` table (migration `0022`). `captureWords` moves from the app to a pure module both the app and the api import (`@robot/scraper/customer-copy`), with the attention banner's sentence beside it. `@robot/api` gets `src/email/`: pure renderers (text + HTML), recipient resolution, `queueEmails` (one row per recipient with a unique dedupe key and one `email` job per row, in one transaction), the `email` job (nodemailer over `SMTP_URL`; empty = `skipped`), `syncAttention` (the `attention_since` claim) called after every write that can change attention, and `notifyRunFailed` next to every `enqueueRunDelivery`. The membership mutations and `ops.enterOrg` queue their messages inside their own transactions (a savepoint that can never fail them). A new `account` router carries the two preferences; the app's Account page gains an "Email" panel. Docker Compose gains a `mailpit` service; a live check runs every message through its real path into a throwaway Mailpit.

**Tech Stack:** TypeScript ESM; Drizzle + Postgres (postgres-js, drizzle-kit migrations); tRPC v11 + zod 3; nodemailer 10 (new dependency of `@robot/api`; ships its own types); `node:net` (the test SMTP sink); vitest; TanStack Start + React 19 + Tailwind v4 + shadcn/radix-ui; Playwright (route smoke); tsx; Docker (Mailpit `axllent/mailpit:v1.32.0`).

**Spec:** `docs/superpowers/specs/2026-10-24-email-design.md`

## Global Constraints

- **Messages** (spec §3.1, verbatim): `attention` — a website turns to "Needs attention" (off → on) — to the org's owners and admins who keep this kind on — subject "<website> needs your attention"; `run-failed` — a run settles `failed` (not a sample) — owners and admins who keep this kind on — "A run of <website> failed"; `staff-access` — staff enter the org (`ops.enterOrg`) — the org's owners and admins (always) — "Our team is working in your organisation"; `role-changed` — `orgs.members.setRole` changes someone's role — that member (always) — "Your role in <org> changed"; `removed` — `orgs.members.remove` removes someone — that former member (always) — "You were removed from <org>". `partial` and `cancelled` runs send nothing. Members (role `member`) never get website or run emails; there is no per-website override.
- **Every message** is plain text plus a simple HTML version with the same content, and names what happened in one or two sentences of customer words, the website, project and organisation names (those that apply), and one link into the app on `PUBLIC_APP_URL` (default `http://localhost:3000`): the website's Verification tab (`/projects/<project slug>/sites/<site slug>`), the run page (`…/runs/<runId>`), Settings (`/settings`), or the sign-in page (`/login`) for a removed member. `attention` and `run-failed` end with the footer "You get this because you look after <org>. Choose which emails you get: <PUBLIC_APP_URL>/account". The `attention` reason is the attention view's own sentence (`attentionSentence`, the Verification banner's text); the `run-failed` reason is the run's stored sentence through `captureWords(text, false)`.
- **Once per event** (§3.2): `sources.attention_since timestamptz`; `syncAttention(db, sourceId)` computes `needsAttention`: on and `attention_since` null → `UPDATE … SET attention_since = now WHERE attention_since IS NULL RETURNING`, and only the writer that wins queues; off → `attention_since` back to null (a later on is a new event). Dedupe keys, unique in `email_messages`: `attention:<sourceId>:<attention_since epoch ms>:<userId>`, `run-failed:<runId>:<userId>`, `staff-access:<staffActionId>:<userId>`, `role-changed:<membershipId>:<newRole>:<epoch ms>:<userId>`, `removed:<orgId>:<userId>:<epoch ms>`. An insert that hits the key does nothing.
- **Queueing** (§3.3): `queueEmails(db, event)` resolves the recipients, renders, and inserts one `email_messages` row per recipient (`id`, `org_id`, `user_id` nullable, `kind`, `dedupe_key` unique, `to_address`, `subject`, `text`, `html`, `status` `queued | sent | failed | skipped`, `attempts`, `error`, `created_at`, `sent_at`) and, in the same transaction, one `email` job per row: background lane, priority 25, 5 attempts, key `email:<messageId>`. Callers: the Verify/drift paths through `syncAttention`; the run-terminal paths next to `enqueueRunDelivery`, each never able to throw into its caller; the two membership mutations and `ops.enterOrg` inside their own transactions.
- **Sending** (§3.3): the worker's `email` job sends the row with nodemailer over `SMTP_URL` (e.g. `smtp://127.0.0.1:1025` for Mailpit, `smtps://user:pass@smtp.provider.com:465`), from `MAIL_FROM` (default `"Robot Platform" <no-reply@localhost>`). Empty `SMTP_URL` = mail off: the row becomes `skipped`, nothing is sent. Success → `sent`; an SMTP error is a failed attempt, retried with the job backoff; after 5 it is `failed` with the stored error. A 15 s connection and send timeout. One message per job.
- **Preferences** (§3.3–§3.4): `users.email_attention boolean not null default true`, `users.email_failed_runs boolean not null default true`; account messages are always sent. Account page: a new "Email" panel, two switches "When a website needs attention" and "When a run fails", each saving on change through `account.updateEmailPrefs`, and one line "Account messages are always sent." Nothing else in the app changes.
- **Local catcher** (§3.5): `docker-compose.yml` gets a `mailpit` service (`axllent/mailpit:v1.32.0`), SMTP on the internal network only, its web UI on `127.0.0.1:${STACK_MAIL_PORT:-8225}`, no volume; the stack's worker gets `SMTP_URL` `smtp://mailpit:1025` by default and the stack's app link base. For `pnpm dev:all`: `docker run -d --name robot-mailpit -p 127.0.0.1:1025:1025 -p 127.0.0.1:8025:8025 axllent/mailpit:v1.32.0` in `.env.example` and `CLAUDE.md`; `SMTP_URL` stays unset in `.env` (mail off by default).
- **Safety** (§4): no email to an address that is not a member of the event's org (a removed member gets exactly the one removal message, built before the delete); at most one message per recipient per event; mail being off, down or slow never changes a run, a Verify, a check or a membership mutation (queueing failures are caught and logged; sending happens in the worker); staff in staff mode never receive customer notification emails because of their own session, and staff-access emails go only to the org's owners and admins.
- **Customer copy:** no money, no HTTP codes, no hosts other than the app link, never "budget", no internals (no model, no "Jev", no job, queue or worker words) — in every rendered subject, text and HTML (`email/render.test.ts`'s sweep) and in the app (`packages/app/src/customer-copy-sweep.test.ts` stays green). The product name appears only in `MAIL_FROM`'s display name.
- **No paid AI.** Nothing in this feature calls a model; every process this plan starts runs with `ANTHROPIC_API_KEY= JEV_SHADOW= TYPESAFE_API_KEY=`.
- **No real mail from tests:** `packages/api/vitest.config.ts` and `packages/worker/vitest.config.ts` set `SMTP_URL: ''` (whatever `.env` says); a test that sends passes its own `env` with the in-process sink's URL. The live check and Docker Compose send only to Mailpit.
- **Marko's data and servers:** never start, stop or restart his dev servers (:3000/:4000) or his worker, never stop or recreate the `robot-platform-db` container, never write a dev-DB row outside tests (tests clean up through their throwaway orgs: `email_messages` cascades from `orgs`). - **Tests:** Postgres is the `robot-platform-db` container (`docker start robot-platform-db` if it is stopped); api tests get a per-file `JOB_QUEUE` automatically (`packages/api/src/test-setup/job-queue.ts`). ## Review Focus

1. **An automatic refresh's own momentary hold** — a drift check that refreshes a price and starts its free re-verify writes a hold for a moment; a person expects no "needs attention" email for a change the product fixed by itself, and the re-verify to decide. → Task 5 test "RF1: a check that started a refresh's re-verify leaves the email to that re-verify".
2. **Names with markup, ampersands or line breaks** (a website called `Tom & Jerry's <b>Shop</b>` followed by `\r\nBcc: x@example.com`) — a person expects the HTML escaped, the subject and every text line one line (no injected header or paragraph). → Task 2 test "RF2: names with markup and line breaks are escaped in HTML and kept on one line".
3. **A mail server that accepts the connection and never answers** — a person expects the attempt to end within the limit, the row to wait for the retry, and a retry after a successful send never to send twice. → Task 4 tests "RF3: a mail server that never answers fails the attempt at the limit" and "RF3: a retry after a send never sends again".
4. **A member removed or demoted** — a person expects them to stop getting website and run emails at once, and a removed member's one message to be built before the membership goes. → Task 6 test "RF4: after a removal and a demotion, a failed run emails only the owners and admins left".
5. **One failed run reported twice** (the executor's catch writes `failed`, then the job layer closes the same run) — a person expects one email per person. → Task 6 test "RF5: a failed run reported by two paths emails each person once".

```ts
// ─── Email (spec 2026-10-24 email §3.3) ─────────────────────────────────────
// One row per message per recipient, written with its `email` job; the worker sends it. The row is the record.

export const EMAIL_KINDS = ['attention', 'run-failed', 'staff-access', 'role-changed', 'removed'] as const;
export type EmailKind = (typeof EMAIL_KINDS)[number];
export const EMAIL_STATUSES = ['queued', 'sent', 'failed', 'skipped'] as const;
export type EmailStatus = (typeof EMAIL_STATUSES)[number];

export const emailMessages = pgTable('email_messages', {
  id: uuid('id').primaryKey().defaultRandom(),
  orgId: uuid('org_id').notNull().references(() => orgs.id, { onDelete: 'cascade' }),
  // Null once the user is deleted; a removed member's row keeps their id (the user still exists).
  userId: uuid('user_id').references(() => users.id, { onDelete: 'set null' }),
  kind: varchar('kind', { length: 20 }).notNull(),
  // One message per recipient per event (spec §3.2): an insert that hits it does nothing.
  dedupeKey: varchar('dedupe_key', { length: 200 }).notNull(),
  toAddress: varchar('to_address', { length: 255 }).notNull(),
  subject: text('subject').notNull(),
  text: text('text').notNull(),
  html: text('html').notNull(),
  status: varchar('status', { length: 10 }).notNull().default('queued'),
  attempts: integer('attempts').notNull().default(0),
  // The last failed attempt's error. Staff only; never shown to a customer.
  error: text('error'),
  createdAt: timestamp('created_at', { withTimezone: true }).defaultNow().notNull(),
  sentAt: timestamp('sent_at', { withTimezone: true }),
}, (table) => [
  uniqueIndex('email_messages_dedupe_key_idx').on(table.dedupeKey),
  index('email_messages_org_created_idx').on(table.orgId, table.createdAt),
]);
```

```ts
/** "a", "a and b", "a, b and c". */
export function joinList(items: string[]): string {
  if (items.length <= 1) return items[0] ?? '';
  if (items.length === 2) return `${items[0]} and ${items[1]}`;
  return `${items.slice(0, -1).join(', ')} and ${items[items.length - 1]}`;
}

const MONTHS = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec'];

/** `d MMM`, e.g. "26 Sep" — locale-free, like the rest of the app's dates (the process's own time zone). */
export function formatDMMM(d: Date): string {
  return `${d.getDate()} ${MONTHS[d.getMonth()]}`;
}

export type AttentionSentenceArgs = {
  fields: string[];
  fieldNames: Record<string, string>;
  goneProducts: number[];
  heldSince: Date | string | null;
  runnable: boolean;
};

/**
 * What needs the customer on a website that changed (spec 2026-10-21 §5): the Verification banner's sentence, and
 * the reason a "needs your attention" email gives. Never names a path, a source, a check, a hold, a model or money.
 */
export function attentionSentence(args: AttentionSentenceArgs): string | null {
  const parts: string[] = [];
  if (args.fields.length > 0) {
    const names = args.fields.map((k) => args.fieldNames[k] ?? k);
    parts.push(`${joinList(names)} ${names.length === 1 ? 'needs' : 'need'} you`);
  }
  if (args.goneProducts.length === 1) parts.push(`product ${args.goneProducts[0]} no longer loads`);
  else if (args.goneProducts.length > 1) parts.push(`products ${joinList(args.goneProducts.map(String))} no longer load`);
  if (parts.length === 0) return null;
  const subject = joinList(parts);
  const tail = !args.runnable
    ? 'extraction waits for you.'
    : args.heldSince
      ? `runs go on with what you verified on ${formatDMMM(new Date(args.heldSince))}.`
      : 'runs go on as before.';
  return `${subject.charAt(0).toUpperCase()}${subject.slice(1)} — ${tail}`;
}
```

```ts
// packages/api/src/email/recipients.ts
// Who an email goes to (spec 2026-10-24 email §3.1, §7): the org's members, read from memberships — never a staff
// session (§4.5: staff are not members). Website and run emails go to owners and admins who keep that kind on;
// account messages ignore preferences.
import { and, eq } from 'drizzle-orm';
import { memberships, users } from '@robot/db';
import type { DbOrTx } from '../jobs/queue.js';

export type Recipient = { userId: string; email: string };
export type MemberRow = Recipient & { role: string; emailAttention: boolean; emailFailedRuns: boolean };
export type Preference = 'attention' | 'failedRuns';

/** Owners and admins, by `pref` (null: always), without `except`; by address, so the order is stable. */
export function lookoutsOf(rows: MemberRow[], pref: Preference | null, except: string | null = null): Recipient[] {
  return rows
    .filter((r) => (r.role === 'owner' || r.role === 'admin') && r.userId !== except)
    .filter((r) => pref === null || (pref === 'attention' ? r.emailAttention : r.emailFailedRuns))
    .sort((a, b) => a.email.localeCompare(b.email))
    .map(({ userId, email }) => ({ userId, email }));
}

async function memberRows(dbh: DbOrTx, orgId: string, userId?: string): Promise<MemberRow[]> {
  return dbh
    .select({ userId: users.id, email: users.email, role: memberships.role, emailAttention: users.emailAttention, emailFailedRuns: users.emailFailedRuns })
    .from(memberships)
    .innerJoin(users, eq(memberships.userId, users.id))
    .where(userId ? and(eq(memberships.orgId, orgId), eq(memberships.userId, userId)) : eq(memberships.orgId, orgId));
}

export async function orgLookouts(dbh: DbOrTx, orgId: string, pref: Preference | null, except: string | null = null): Promise<Recipient[]> {
  return lookoutsOf(await memberRows(dbh, orgId), pref, except);
}

/** That user while they are a member of the org (any role); null otherwise. */
export async function orgMember(dbh: DbOrTx, orgId: string, userId: string): Promise<Recipient | null> {
  const [r] = await memberRows(dbh, orgId, userId);
  return r ? { userId: r.userId, email: r.email } : null;
}
```

```ts
// packages/api/src/email/queue-emails.ts
// Spec 2026-10-24 email §3.2–§3.3: an event becomes one email_messages row per recipient — rendered now, with its
// unique dedupe key — and one `email` job per row, in one transaction (a savepoint inside a caller's). A key already
// taken inserts nothing and enqueues nothing. The api-server never reads SMTP_URL (spec §6): whether mail is on is
// the worker's to know, and its job marks the row skipped.
import { eq } from 'drizzle-orm';
import { datasets, emailMessages, orgs, projects, runs, sources, type MembershipRole } from '@robot/db';
import type { SchemaDefinitionField } from '@robot/scraper';
import { attentionSentence } from '@robot/scraper/customer-copy';
import type { DbOrTx } from '../jobs/queue.js';
import { enqueue } from '../jobs/enqueue.js';
import type { Attention } from '../verify/attention.js';
import { publicAppUrl, type Env } from './config.js';
import { attentionEmail, removedEmail, roleChangedEmail, runFailedEmail, staffAccessEmail, type RenderedEmail } from './render.js';
import { orgLookouts, orgMember, type Recipient } from './recipients.js';

export type EmailEvent =
  | { kind: 'attention'; sourceId: string; since: Date; attention: Pick<Attention, 'fields' | 'goneProducts' | 'heldSince'>; runnable: boolean }
  | { kind: 'run-failed'; runId: string }
  | { kind: 'staff-access'; staffActionId: string; orgId: string; actorUserId: string; sourceId: string | null }
  | { kind: 'role-changed'; membershipId: string; orgId: string; userId: string; role: MembershipRole; at: Date }
  | { kind: 'removed'; orgId: string; userId: string; at: Date };

/** Spec §3.2, verbatim. */
export function dedupeKey(event: EmailEvent, userId: string): string {
  switch (event.kind) {
    case 'attention': return `attention:${event.sourceId}:${event.since.getTime()}:${userId}`;
    case 'run-failed': return `run-failed:${event.runId}:${userId}`;
    case 'staff-access': return `staff-access:${event.staffActionId}:${userId}`;
    case 'role-changed': return `role-changed:${event.membershipId}:${event.role}:${event.at.getTime()}:${userId}`;
    case 'removed': return `removed:${event.orgId}:${userId}:${event.at.getTime()}`;
  }
}

export function emailJobKey(messageId: string): string {
  return `email:${messageId}`;
}

type Built = { orgId: string; recipients: Recipient[]; rendered: RenderedEmail };

/** A customer website's names and slugs; null for a website with no project (a sandbox). */
async function websitePlace(dbh: DbOrTx, sourceId: string) {
  const [w] = await dbh
    .select({
      orgId: orgs.id, org: orgs.name, project: projects.name, projectSlug: projects.slug,
      website: sources.name, siteSlug: sources.slug, schemaDefinition: sources.schemaDefinition,
    })
    .from(sources)
    .innerJoin(datasets, eq(sources.datasetId, datasets.id))
    .innerJoin(projects, eq(datasets.projectId, projects.id))
    .innerJoin(orgs, eq(projects.orgId, orgs.id))
    .where(eq(sources.id, sourceId))
    .limit(1);
  return w ?? null;
}

async function orgName(dbh: DbOrTx, orgId: string): Promise<string | null> {
  const [o] = await dbh.select({ name: orgs.name }).from(orgs).where(eq(orgs.id, orgId)).limit(1);
  return o?.name ?? null;
}

async function build(dbh: DbOrTx, event: EmailEvent, base: string): Promise<Built | null> {
  switch (event.kind) {
    case 'attention': {
      const w = await websitePlace(dbh, event.sourceId);
      if (!w) return null;
      const fields = (Array.isArray(w.schemaDefinition) ? w.schemaDefinition : []) as SchemaDefinitionField[];
      const reason = attentionSentence({ ...event.attention, fieldNames: Object.fromEntries(fields.map((f) => [f.key, f.name])), runnable: event.runnable })
        ?? 'Something on this website needs you.';
      return { orgId: w.orgId, recipients: await orgLookouts(dbh, w.orgId, 'attention'), rendered: attentionEmail({ base, ...w, reason }) };
    }
    case 'run-failed': {
      const [r] = await dbh.select({ sourceId: runs.sourceId, status: runs.status, inputLabel: runs.inputLabel, errorMessage: runs.errorMessage })
        .from(runs).where(eq(runs.id, event.runId)).limit(1);
      // Spec §3.1, §7: only `failed`, never a sample.
      if (!r?.sourceId || r.status !== 'failed' || r.inputLabel === 'probe') return null;
      const w = await websitePlace(dbh, r.sourceId);
      if (!w) return null;
      return { orgId: w.orgId, recipients: await orgLookouts(dbh, w.orgId, 'failedRuns'), rendered: runFailedEmail({ base, ...w, runId: event.runId, stored: r.errorMessage }) };
    }
    case 'staff-access': {
      const org = await orgName(dbh, event.orgId);
      if (org === null) return null;
      const w = event.sourceId ? await websitePlace(dbh, event.sourceId) : null;
      const here = w && w.orgId === event.orgId ? w : null;
      return {
        orgId: event.orgId,
        // §4.5: never the operator who entered, even one who is a member of this org.
        recipients: await orgLookouts(dbh, event.orgId, null, event.actorUserId),
        rendered: staffAccessEmail({ base, org, website: here?.website ?? null, project: here?.project ?? null }),
      };
    }
    case 'role-changed':
    case 'removed': {
      const org = await orgName(dbh, event.orgId);
      // §4.1: only while they are a member — a removal is queued before its delete.
      const who = org === null ? null : await orgMember(dbh, event.orgId, event.userId);
      if (org === null || !who) return null;
      const rendered = event.kind === 'role-changed' ? roleChangedEmail({ base, org, role: event.role }) : removedEmail({ base, org });
      return { orgId: event.orgId, recipients: [who], rendered };
    }
  }
}

export async function queueEmails(dbh: DbOrTx, event: EmailEvent, opts: { env?: Env } = {}): Promise<{ queued: string[] }> {
  return dbh.transaction(async (tx) => {
    const built = await build(tx, event, publicAppUrl(opts.env));
    if (!built) return { queued: [] };
    const queued: string[] = [];
    for (const r of built.recipients) {
      const [row] = await tx.insert(emailMessages)
        .values({ orgId: built.orgId, userId: r.userId, kind: event.kind, dedupeKey: dedupeKey(event, r.userId), toAddress: r.email, ...built.rendered })
        .onConflictDoNothing({ target: emailMessages.dedupeKey })
        .returning({ id: emailMessages.id });
      if (!row) continue;
      await enqueue(tx, 'email', { messageId: row.id }, { key: emailJobKey(row.id) });
      queued.push(row.id);
    }
    return { queued };
  });
}

/**
 * Spec §4.3: mail never changes the run, Verify, check or mutation that caused it. Inside a caller's transaction a
 * failure undoes only this savepoint; the caller's writes go on.
 */
export async function queueEmailsSafely(dbh: DbOrTx, event: EmailEvent, opts: { env?: Env } = {}): Promise<number> {
  try {
    return (await queueEmails(dbh, event, opts)).queued.length;
  } catch (err) {
    console.error(`[email] ${event.kind} emails could not be queued:`, err);
    return 0;
  }
}
```

```ts
// packages/api/src/test-helpers/smtp-sink.ts
// A tiny SMTP server for tests (spec 2026-10-24 email §5: an in-process sink, no Docker). It speaks just enough of
// RFC 5321 for nodemailer — EHLO/HELO, MAIL, RCPT, DATA, RSET, NOOP, QUIT; no TLS, no AUTH — and keeps what it got.
// `failNext` answers that many messages with a temporary 451; `silent` accepts connections and never greets.
import { createServer, type AddressInfo, type Socket } from 'node:net';

export type SunkMessage = { from: string; to: string[]; data: string };
export type SmtpSink = { url: string; messages: SunkMessage[]; failNext: number; silent: boolean; close(): Promise<void> };

export async function startSmtpSink(): Promise<SmtpSink> {
  const sockets = new Set<Socket>();
  const sink: SmtpSink = { url: '', messages: [], failNext: 0, silent: false, close: async () => {} };
  const server = createServer((sock) => {
    sockets.add(sock);
    sock.on('close', () => sockets.delete(sock));
    sock.on('error', () => {});
    if (sink.silent) return;
    sock.setEncoding('utf8');
    const say = (line: string) => { if (!sock.destroyed) sock.write(`${line}\r\n`); };
    const fresh = (): SunkMessage => ({ from: '', to: [], data: '' });
    let buf = '';
    let inData = false;
    let cur = fresh();
    say('220 sink.test ESMTP');
    sock.on('data', (chunk: string) => {
      buf += chunk;
      for (;;) {
        if (inData) {
          const end = buf.indexOf('\r\n.\r\n');
          if (end < 0) return;
          cur.data = buf.slice(0, end);
          buf = buf.slice(end + 5);
          inData = false;
          if (sink.failNext > 0) { sink.failNext--; say('451 4.3.0 Try again later'); } else { sink.messages.push(cur); say('250 2.0.0 Queued'); }
          cur = fresh();
          continue;
        }
        const nl = buf.indexOf('\r\n');
        if (nl < 0) return;
        const line = buf.slice(0, nl);
        buf = buf.slice(nl + 2);
        const verb = line.slice(0, 4).toUpperCase();
        const address = () => /<([^>]*)>/.exec(line)?.[1] ?? '';
        if (verb === 'EHLO') { say('250-sink.test'); say('250 8BITMIME'); }
        else if (verb === 'HELO') say('250 sink.test');
        else if (verb === 'MAIL') { cur.from = address(); say('250 2.1.0 OK'); }
        else if (verb === 'RCPT') { cur.to.push(address()); say('250 2.1.5 OK'); }
        else if (verb === 'DATA') { inData = true; say('354 End data with <CR><LF>.<CR><LF>'); }
        else if (verb === 'RSET') { cur = fresh(); say('250 2.0.0 OK'); }
        else if (verb === 'QUIT') { say('221 2.0.0 Bye'); sock.end(); return; }
        else say('250 2.0.0 OK');
      }
    });
  });
  await new Promise<void>((resolve) => server.listen(0, '127.0.0.1', resolve));
  sink.url = `smtp://127.0.0.1:${(server.address() as AddressInfo).port}`;
  sink.close = async () => {
    for (const s of sockets) s.destroy();
    await new Promise<void>((resolve) => server.close(() => resolve()));
  };
  return sink;
}
```

```ts
// packages/api/src/email/smtp.ts
// One message over SMTP with nodemailer (spec 2026-10-24 email §3.3): SMTP_URL as given — smtp:// (STARTTLS when the
// server offers it) or smtps:// (TLS), credentials in the URL — so a real provider is configuration only (§6).
// A 15 s limit on connecting, on the greeting, on each read, and on the whole send.
import nodemailer, { type SMTPTransportOptions } from 'nodemailer';

export const SEND_TIMEOUT_MS = 15_000;

export type OutgoingMail = { from: string; to: string; subject: string; text: string; html: string };

export function smtpOptions(url: string, timeoutMs = SEND_TIMEOUT_MS): SMTPTransportOptions {
  if (!/^smtps?:\/\//i.test(url)) throw new Error('SMTP_URL must start with smtp:// or smtps://');
  return { url, connectionTimeout: timeoutMs, greetingTimeout: timeoutMs, socketTimeout: timeoutMs };
}

export async function sendSmtp(url: string, mail: OutgoingMail, timeoutMs = SEND_TIMEOUT_MS): Promise<void> {
  const transport = nodemailer.createTransport(smtpOptions(url, timeoutMs));
  let timer: ReturnType<typeof setTimeout> | undefined;
  try {
    await Promise.race([
      transport.sendMail(mail),
      new Promise<never>((_, reject) => { timer = setTimeout(() => reject(new Error(`the mail server did not finish within ${timeoutMs} ms`)), timeoutMs); }),
    ]);
  } finally {
    clearTimeout(timer);
    transport.close();
  }
}
```

```ts
// packages/api/src/email/send-email.ts
// The `email` job (spec 2026-10-24 email §3.3): sends one email_messages row from MAIL_FROM over SMTP_URL. Mail off
// (SMTP_URL empty) marks it skipped. A failed send is a failed attempt — recorded, thrown, retried with the job's
// backoff — and the fifth is final (`failed`). A row no longer queued (sent, skipped, failed, or gone with its org)
// is never sent again. One message per job, so one recipient's failure never blocks another's.
import { and, eq } from 'drizzle-orm';
import { db, emailMessages } from '@robot/db';
import type { JobContext } from '../jobs/context.js';
import type { JobPayloads } from '../jobs/types.js';
import { mailFrom, smtpUrl, type Env } from './config.js';
import { SEND_TIMEOUT_MS, sendSmtp } from './smtp.js';

/** JOB_POLICIES.email.maxAttempts — pinned equal by send-email.test.ts. */
export const EMAIL_ATTEMPTS = 5;

export class EmailNotSent extends Error {}

export async function sendEmailJob(
  p: JobPayloads['email'],
  ctx: Pick<JobContext, 'attempt'>,
  deps: { env?: Env; send?: typeof sendSmtp; timeoutMs?: number } = {},
): Promise<{ status: 'sent' | 'skipped' | 'none' }> {
  const env = deps.env ?? process.env;
  const [row] = await db.select().from(emailMessages).where(eq(emailMessages.id, p.messageId)).limit(1);
  if (!row || row.status !== 'queued') return { status: 'none' };
  const stillQueued = and(eq(emailMessages.id, row.id), eq(emailMessages.status, 'queued'));
  const url = smtpUrl(env);
  if (!url) {
    await db.update(emailMessages).set({ status: 'skipped' }).where(stillQueued);
    return { status: 'skipped' };
  }
  try {
    await (deps.send ?? sendSmtp)(url, { from: mailFrom(env), to: row.toAddress, subject: row.subject, text: row.text, html: row.html }, deps.timeoutMs ?? SEND_TIMEOUT_MS);
  } catch (err) {
    const error = (err instanceof Error ? err.message : String(err)).slice(0, 1000);
    const last = ctx.attempt >= EMAIL_ATTEMPTS;
    await db.update(emailMessages).set({ attempts: ctx.attempt, error, ...(last ? { status: 'failed' } : {}) }).where(stillQueued);
    throw new EmailNotSent(`email not sent: ${error}`);
  }
  await db.update(emailMessages).set({ status: 'sent', attempts: ctx.attempt, error: null, sentAt: new Date() }).where(eq(emailMessages.id, row.id));
  return { status: 'sent' };
}
```

```ts
// packages/api/src/email/attention-sync.ts
// Spec 2026-10-24 email §3.2: "Needs attention" is computed, not stored; `attention_since` records the turn. After
// every write that can change it (a Verify, a finished check, an edit), this computes it: on, with attention_since
// null → claim it (`WHERE attention_since IS NULL`) and only the writer that wins queues the emails, in the same
// transaction; off → back to null, so a later turn is a new event. A claim whose queueing throws rolls back: the
// next sync tries again.
import { and, eq, isNotNull, isNull } from 'drizzle-orm';
import { sources, type Database } from '@robot/db';
import { needsAttention, websiteAttention } from '../verify/attention.js';
import { loadCertificationState, runnableOf } from '../verify/current-certification.js';
import { queueEmails } from './queue-emails.js';

export type AttentionSync = { on: boolean; turnedOn: boolean; queued: number };

export async function syncAttention(dbh: Database, sourceId: string, deps: { now?: () => Date } = {}): Promise<AttentionSync> {
  const attention = await websiteAttention(dbh, sourceId);
  if (!needsAttention(attention)) {
    await dbh.update(sources).set({ attentionSince: null }).where(and(eq(sources.id, sourceId), isNotNull(sources.attentionSince)));
    return { on: false, turnedOn: false, queued: 0 };
  }
  const runnable = runnableOf(await loadCertificationState(dbh, sourceId));
  const now = deps.now?.() ?? new Date();
  return dbh.transaction(async (tx) => {
    const [won] = await tx.update(sources).set({ attentionSince: now })
      .where(and(eq(sources.id, sourceId), isNull(sources.attentionSince)))
      .returning({ since: sources.attentionSince });
    if (!won?.since) return { on: true, turnedOn: false, queued: 0 };
    const { queued } = await queueEmails(tx, { kind: 'attention', sourceId, since: won.since, attention, runnable });
    return { on: true, turnedOn: true, queued: queued.length };
  });
}

/** Spec §4.3: never throws — mail never changes the Verify, check or edit that called it. */
export async function syncAttentionSafely(dbh: Database, sourceIds: string | string[]): Promise<void> {
  for (const id of Array.isArray(sourceIds) ? sourceIds : [sourceIds]) {
    try {
      await syncAttention(dbh, id);
    } catch (err) {
      console.error(`[email] "needs attention" for website ${id} could not be synced:`, err);
    }
  }
}
```

```ts
// packages/api/src/routers/account.ts
// The signed-in person's own email preferences (spec 2026-10-24 email §3.3–§3.4): "When a website needs attention"
// and "When a run fails". Account messages are always sent. For staff working in a customer's org it is still their
// own account (ctx.session.user is the operator).
import { z } from 'zod';
import { eq } from 'drizzle-orm';
import { users } from '@robot/db';
import { router, protectedProcedure } from '../trpc.js';

export type EmailPrefs = { attention: boolean; failedRuns: boolean };

const prefsOf = (u: { emailAttention: boolean; emailFailedRuns: boolean }): EmailPrefs => ({ attention: u.emailAttention, failedRuns: u.emailFailedRuns });

export const accountRouter = router({
  emailPrefs: protectedProcedure.query(async ({ ctx }): Promise<EmailPrefs> => {
    const u = await ctx.db.query.users.findFirst({ where: eq(users.id, ctx.session.user.id), columns: { emailAttention: true, emailFailedRuns: true } });
    return prefsOf(u ?? { emailAttention: true, emailFailedRuns: true });
  }),

  /** Saves on change (the panel's switches): only the preferences given change. */
  updateEmailPrefs: protectedProcedure
    .input(z.object({ attention: z.boolean().optional(), failedRuns: z.boolean().optional() }))
    .mutation(async ({ ctx, input }): Promise<EmailPrefs> => {
      const [u] = await ctx.db.update(users).set({
        ...(input.attention === undefined ? {} : { emailAttention: input.attention }),
        ...(input.failedRuns === undefined ? {} : { emailFailedRuns: input.failedRuns }),
        updatedAt: new Date(),
      }).where(eq(users.id, ctx.session.user.id)).returning({ emailAttention: users.emailAttention, emailFailedRuns: users.emailFailedRuns });
      return prefsOf(u!);
    }),
});
```

```tsx
/**
 * Which emails this person gets (spec 2026-10-24 email §3.4). Each switch saves on change — shown at once, put back
 * if the save fails; account messages are always sent.

export function EmailPanel() {
  const utils = trpc.useUtils();
  const prefs = trpc.account.emailPrefs.useQuery();
  const update = trpc.account.updateEmailPrefs.useMutation({
    onMutate: (patch) => {
      const before = utils.account.emailPrefs.getData();
      if (before) utils.account.emailPrefs.setData(undefined, { ...before, ...patch });
      return { before };
    },
    onError: (_err, _patch, context) => {
      if (context?.before) utils.account.emailPrefs.setData(undefined, context.before);
    },
    onSuccess: (saved) => utils.account.emailPrefs.setData(undefined, saved),
  });

  function change(key: keyof EmailPrefs, on: boolean) {
    update.mutate(key === 'attention' ? { attention: on } : { failedRuns: on });
  }

  return (
    <section className="rise rounded-[6px] border border-line bg-panel [box-shadow:var(--shadow)]">
      <h2 className="border-b border-line px-4 py-3 text-base font-medium">Email</h2>
      <div className="space-y-2 px-4 py-3">
        {emailPrefRows(prefs.data).map((r) => (
          <div key={r.key} className="flex items-center gap-3">
            <Switch id={`email-${r.key}`} checked={r.checked} disabled={r.disabled} onCheckedChange={(on) => change(r.key, on)} />
            <Label htmlFor={`email-${r.key}`} className="text-base font-normal">{r.label}</Label>
          </div>
        ))}
        <p className="pt-1 text-sm text-muted-foreground">{ACCOUNT_MESSAGES_LINE}</p>
        {prefs.isError ? <p role="alert" className="text-sm text-fail">{EMAIL_PREF_LOAD_FAILED}</p> : null}
        {update.isError ? <p role="alert" className="text-sm text-fail">{EMAIL_PREF_SAVE_FAILED}</p> : null}
      </div>
    </section>
  );
```

## Settled here (spec ambiguities, decided for this plan)

1. **Where `captureWords` lives** — moved, not copied: `@robot/scraper/customer-copy` (`packages/scraper/src/customer-copy.ts`), a pure module with no imports. Both packages already depend on `@robot/scraper` and the app already imports its pure `/normalize` subpath at runtime; `@robot/app`'s `lib/capture-words.ts` re-exports it, so the app's twenty call sites and its capture-words test are unchanged, and a new test pins that the app's function *is* the shared one. `joinList`, `formatDMMM` and the attention sentence move with it.
2. **The `attention` reason** — the Verification banner's sentence (`attentionSentence`, now shared; `attentionBanner` = its drift guard + this). The email ignores the drift guard: `needsAttention` does not look at drift either. Its date is formatted in the sending process's time zone, as the app formats in the viewer's.
3. **"Rows are written as skipped"** — the api-server never reads `SMTP_URL` (spec §6), so `queueEmails` writes `queued` rows everywhere and the `email` job marks a row `skipped` when the worker's `SMTP_URL` is empty.
4. **`syncAttention` after the Verify transaction, not inside it** — `websiteAttention` reads committed rows through the database handle; calling it in `runSourceVerification`'s `finally` (any outcome: a pass, a held field, a failure; never a stopped attempt) sees what the Verify wrote. A crash between the commit and the sync is healed by the next sync.
5. **A check that refreshed values** — it starts a free re-verify and does not sync; the re-verify (a Verify) does. An automatic refresh holds its field only until that re-verify, so syncing at the check's end would email "needs attention" for a change the product fixed itself (Review Focus 1).
6. **"An edit that clears a hold"** — `sources.updateBinding` and `datasets.addField/renameField/retypeField/deleteField`, every path that changes a field's hash (`fieldHash`: the field, its expected values, marks, paths, absences, default). Variant setup and answers do not enter the hash and are not wired. **Also a fourth run-terminal path:** the `scheduled-run` job notifies for a run it leaves failed (its failed plan, nothing planned, certification lost, a start that threw) — nobody watches a scheduled run start, and the spec's three paths never see these. Manual plan failures (the customer is on screen) do not email, unless the job layer closes them.
7. **Backfill and repair runs** that fail email like any run (their own run page); samples (`input_label = 'probe'`) never.
8. **Staff access** — the acting operator is never a recipient, even when they are an owner or admin of that org (§4.5's intent). Entering the org the session is already in writes no `staff_actions` row and sends nothing; leaving and entering again is a new visit. `recordStaffAction` now returns the row id (the dedupe key needs it).
9. **`setRole` to the same role** changes nothing and sends nothing (the spec's "changes someone's role").
10. **The account procedures** — a new `account` router: `account.updateEmailPrefs` (the spec's name) and `account.emailPrefs` (the panel needs the saved values; the session does not carry them). Staff: their own account — not logged in `staff_actions`, allowed after the 8 hours, like `auth.setTheme`.
11. **The switches** — a new `components/ui/switch.tsx` (shadcn's switch on `radix-ui`'s Switch, already installed), saving optimistically and putting the value back if the save fails. Copy the spec did not word: "The preference could not be saved. Try again." and "Your email choices could not be loaded. Reload the page."
12. **Message copy the spec did not word** — paragraphs and link labels as in `render.ts` ("Open the website", "Open the run", "Open Settings", "Sign in"); facts as `Website:`/`Project:`/`Organisation:` lines; a role named "an owner", "an admin", "a member". The removed member's link is `/login`.
13. **nodemailer 10, no `@types/nodemailer`** — the current major ships its own types; `@types/nodemailer` describes older majors. `SMTP_URL` is handed to nodemailer as its `url` option (credentials and `smtps` parsed by nodemailer), refused unless it starts with `smtp://` or `smtps://`. The 15 s limit is nodemailer's connection, greeting and socket timeouts plus one race on the whole send.
14. **The test SMTP sink** — `node:net`, in-process (`test-helpers/smtp-sink.ts`), not the `smtp-server` package: four behaviours (accept, a temporary 451, silence, keep the message) with no new dependency.
15. **Docker** — Mailpit pinned to `axllent/mailpit:v1.32.0` (the newest stable tag on 2026-10-24); its SMTP is not published; no volume (its default store lives and dies with the container). The stack's worker sends to `${STACK_SMTP_URL:-smtp://mailpit:1025}` — compose reads `STACK_*` from `.env`/the shell, so a provider for the stack is `STACK_SMTP_URL` (an `SMTP_URL` in `stack.env` is overridden by `environment`). The api and worker get `PUBLIC_APP_URL` = the stack's app port.
16. **`email_messages.user_id`** is `ON DELETE SET NULL` (the row stays the record); `org_id` cascades (an org's messages go with it, like everything else of it).
17. **A website that already needed attention when this ships** sends one email at its first sync after the deploy (`attention_since` starts null) — recorded under Open in the handoff.
18. **`JOB_POLICIES.email.stuckMs`** is 2 minutes (a send is bounded at 15 s).
