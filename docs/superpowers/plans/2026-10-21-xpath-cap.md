# Cap XPath backups too Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Count the page's HTML as one source under the two-per-source cap, re-search all-XPath cached certifications, and warn in ops on all-XPath fields.

**Architecture:** Drop the 2026-10-20 XPath exemption in the scraper (`certify.ts`, `run-verification.ts` follows from `readsOneSource`) and its mirror in the app (`ops-view.ts`); the shared seven-case table keeps the two in step.

**Tech Stack:** TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-xpath-cap-design.md`

## Global Constraints

- `MAX_PATHS_PER_SOURCE` = 2, `MAX_CERTIFIED_PATHS` = 5 (`packages/scraper/src/verify/constants.ts`), unchanged.
- Ops warning text unchanged: "All backups read the same response — if it changes, they fail together".
- The cache shortcut's search again is free: no AI call (prove it with a spy agent that throws).
- The app may not import `@robot/scraper` (except `/normalize`): the rule stays mirrored, with the same case table in both test files.

## Review Focus

- A multi-layout cover of three or more XPaths must keep every layout's path (covers are not capped).
- An all-XPath cached certification on pages with JSON-LD: JSON-LD joins, two XPaths stay.
- An XPath beside a JSON-LD path from the cache: kept without a search.
- XPaths beside one API response: two from each, the best (API) first.
- An all-XPath cached certification on pages with nothing else: the same two XPaths, no AI call.
