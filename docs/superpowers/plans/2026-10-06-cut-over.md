**Goal:** `@robot/app` covers everything a person needs. Customers can rename a project. Operators get a cross-customer overview and a per-website certificate page. The old dashboard (`packages/dashboard`) and everything that exists only for it are deleted.

  - its scripts and its `:3456` CORS origin;
  - the session-less `DEFAULT_ORG_SLUG` shim;
  - every tRPC procedure only it used;
  - the already-dead `scraper.*` procedures.

**Tech Stack:** tRPC v11 + zod, Drizzle (no migration), TanStack Start/Router/Query, Tailwind tokens, vitest, pnpm workspaces.

## Ops design (UX, binding for Tasks 2–4)

**Reference mockup** (example data, the app's own tokens and type): https://claude.ai/artifact/MaSvvyEbzvr4MbmQeh5WEa. Its source is in the controller's scratchpad, `ops-mockup/ops-mockup.html`. Match it unless this section says otherwise.

**Who and why.** The product owner and team (operators) use ops to answer one question on any morning: *which customer websites need us, and why?* Then they look closer at one website. Ops never changes anything; fixing happens in the app as a member of the customer's org.

**Visual system.** Ops follows the app's visual system exactly (redesign spec §4):
- Geist and Geist Mono, monochrome, the app tokens.
- State shown only as a dot, a 2 px rail or a text colour, never a wash.
- Tables first. One fade-up on load. The run dot keeps its meaning.

The one distinctive element is the **try-order ladder** on the website page. Nothing else gets new decoration.

### Ops mode (Marko, 2026-10-06: staff live in ops, not in a customer's workspace)
- **Landing:** after sign-in, an operator (`ops.me.isOperator`) lands on `/ops`, not `/projects`. `/` redirects operators to `/ops`.
- **Its own shell.** Under `/ops/*` the sidebar is the ops shell:
  - **Top:** in place of the org switcher, a static header "Robot ops", with "Staff" on the right in secondary text.
  - **Nav:** one item, "All websites" (list icon). Later staff pages slot in here.
  - **Missing on purpose:** Projects, Runs, Usage, Settings and the org switcher.
  - **At the bottom,** above the account row and only when the operator is a member of at least one org: "Switch to customer view", which goes to `/projects` in their current or first org.
- **The customer shell gains,** for operators only, a "Back to ops" item at the bottom of its sidebar. Customers never see either link.
- **A staff account with no org memberships** never sees customer screens. `/projects` and the other org routes redirect it to `/ops`.
- **One sign-in, no separate login** (overkill for now). The server's FORBIDDEN on every `ops.*` call is the real gate; the shells only decide what's shown.
- **Not in this plan:** staff working inside a customer's websites without membership (Marko: later). "Open in the app" stays disabled for non-members.

### `/ops` — All websites
- **Top bar:** breadcrumb "Ops / All websites".
- **Header:**
  - **Left:** title "All websites", with the subtitle "Every customer's websites, the ones that need you first."
  - **Right:** "Updated {relative time}" in secondary text, then a **Refresh** button (outline). It refetches; the query also refetches on window focus and every 60 s.
- **Toolbar** (one row, wraps on narrow screens):
  1. **Segmented control:** "Needs attention {n}" and "All {n}". The default is *Needs attention* when its count is above 0, otherwise *All*.
  2. **Search input:** "Search customers, websites or addresses". It filters as you type, matching website name, host, customer and project.
  3. **Customer select:** "All customers", then each customer name.
- **Reason chips** (only in *Needs attention*, under the toolbar): "Stopped extracting {n}", "Last run failed {n}", "Not fully verified {n}".
  - A chip is shown only when its count is above 0.
  - Clicking one narrows the table to that reason; clicking it again clears it. At most one chip is active.
- **Shareable state:** view, reason, search, customer and sort live in the URL search params (`?view=all&reason=drift&q=nike&customer=<orgId>&sort=spend-desc`), so a link shows exactly what you saw.
- **Table:** one row per website, hairline rows, a raised row on hover, and the header sticky from `md` up.
  - **Website:**
    - the name is the only link, to `/ops/websites/{sourceId}`, underlined on hover;
    - the host is under it in mono;
    - under that, the problem line in its state colour: warn "{n} fields stopped extracting" / "1 field stopped extracting", or fail "Last run failed".
  - **Customer and project:** the customer name is a text button ("Show only {customer}'s websites"), which sets the customer filter. The project name is under it in secondary text.
  - **Verified:** a 2 px rail plus a label:
    - pass rail, "{n} of {n} fields";
    - warn rail, "{c} of {n} fields";
    - fail rail, "Not verified".
  - **Last run** (right-aligned): the run dot plus a mono relative time ("35 min ago", "Running"), or "No runs".
  - **This month** (right-aligned, mono): "$3.42", or "—" for 0.
- **Sorting:**
  - **Default order:** stopped extracting, then last run failed, then not fully verified, then the rest. Within each group, most recent activity first.
  - **Sortable headers:** "Last run" and "This month" are header buttons (`aria-sort`). Clicking once sorts, clicking again reverses the order.
  - **Footer:** the footer's right side states the current order: "Sorted by what needs you, then most recent activity", or "Sorted by last run" / "by spend this month".
- **Footer left:** "{n} websites across {m} customers".
- **Empty states:**
  - **Nothing needs attention:** a pass dot, "Nothing needs you right now." and, in secondary text, "All {n} websites are verified and their last runs finished.", then a "Show all websites" button.
  - **Search or filters match nothing:** "No websites match." and a "Clear search and filters" button.
  - **No customer websites at all:** "No customer websites yet. They appear here as soon as a customer adds one."
- **Loading and errors:**
  - **Loading:** three skeleton rows the shape of real ones.
  - **Error:** "Couldn't load websites." with a Retry button. The message comes from the API, never a stack trace.

### `/ops/websites/$sourceId` — one website
- **Top bar:** breadcrumb "Ops / All websites / {website}"; the first two crumbs link back, keeping the overview's URL state.
- **Header:**
  - **Left:** title {website}, with the host under it as an external mono link.
  - **Right:** **Visit website** (outline, external), then **Open in the app** (primary). Open in the app goes to `/projects/{slug}/sites/{slug}`. When the operator isn't a member of that org it is disabled (`aria-disabled`, muted), with the tooltip "You're not a member of {customer}".
- **Summary strip:** one bordered row of five cells that wraps on narrow screens:
  - **Customer.**
  - **Project.**
  - **Verified:** rail plus label, as in the table.
  - **Last run:** the dot plus "Completed 2 h ago, 1,248 rows", "Failed 35 min ago", "Running" or "No runs".
  - **Stopped extracting:** a warn rail plus the field names joined ("Price and Size"), or "None".
- **What changed** notice: shown only when the latest drift check has results and the website still has drifted fields.
  - **Style:** a panel with a warn left rail, titled "What changed in the run of {d MMM}".
  - **Content:** one line per drifted field — the field name, then the drift row text from the Verification tab (`moved` → "Moved on the page — a new location is proposed", `changed` → "Page now shows {new} (was {old})", `other-layout` → "Still works on the proof pages; some other products differ", `lost` → "Not found on the page", plus "Product {n} no longer loads").
  - **Footer line,** in secondary text: "Repairs are accepted on the website's Verification tab in the app."
- **Approved paths** section:
  - **Heading:** "Approved paths", with the subtitle "Tried in order on every product page; the first that finds a value is used. Run counts cover every run on {host}." The domain store's stats are per host, across every website on it; the subtitle says so.
  - **Expand all / Collapse all:** a text button on the right.
- **One disclosure row per contract field,** in contract order. The row is a button (`aria-expanded`, `aria-controls`) with a chevron.
  - **Collapsed, it shows:**
    - the field name (medium) and its type (secondary);
    - the first path's kind and backup count ("API, 2 backups", "Page data, no backups");
    - "First path {pct} %", or "Not needed yet";
    - a warn flag on the right, the first of these that applies: "Stopped extracting" (the field is drifted), "Backups share one source", or "First path finds it on {pct} %" (below 90 %).
  - **Default state:** fields with a flag start expanded; the others start collapsed.
- **The ladder** (expanded): an ordered list. The numbers are the real try order; a 2 px rail joins the steps, and step 1's circle is in `--text`. Each step shows:
  - **The kind:** "API", "Page data", "Meta" or "Page element".
  - **The path,** in mono, truncated with the full path in its `title`. A "Copy" text button appears on row hover or focus; it says "Copied" for 1.2 s, and on refusal it selects the text.
  - **Proven on:** "all proof pages" or "products 1 and 3".
  - **In runs:** "{hits} of {uses} ({pct} %)" with a 2 px bar at that width. The bar is `--text`, or warn when it is step 1 and below 90 %. With 0 uses the step reads "Not needed yet" in secondary text, with no bar.
  - **One-source note:** under the ladder, when it applies, a warn-rail line: "All backups read the same response — if it changes, they fail together" (the Global Constraints wording)
- **Proof pages** section: "Proof pages", subtitle "The products these paths were verified on.", then each URL as an external mono link, "Product {n}: {host/path}".
- **Loading and errors:**
  - **Loading:** a skeleton strip, then three skeleton field rows.
  - **A source that doesn't exist or isn't a customer-schema website:** "This website isn't in ops." with a link back to All websites.

### Task 4: Ops website page — the approved paths, readable

**Files:** modify `ops.ts` (`ops.website({ sourceId })`) and its tests; modify `packages/app/src/lib/ops-view.ts` (`pathKind`, `provenText`, `runStatsText`, `oneSourceWarning`) and its test; create `packages/app/src/routes/_app/ops/websites/$sourceId.tsx`.

**Interfaces — Produces:**

```ts
ops.website → {
  sourceId: string; org: {...}; project: {...}; website: {...}; operatorIsMember: boolean;
  fields: Array<{ key: string; name: string; type: string;
    paths: Array<{ source: 'api' | 'json-ld' | 'meta' | 'xpath'; path: string; provenOn?: string[]; uses: number; hits: number; container?: string }>;
  }>;
  drift: { status: string; results: unknown } | null;   // latest drift check, as sources.driftCheck returns it

}
```

**Rules:**
- **Paths:** `fields` come from `loadCurrentCertification`'s `paths`, in try order, named with the contract's field names.
- **Stats:** `uses`/`hits` come from the domain store's per-path stats for `(cert.hostname, 'detail', concept)` (read `domain-cache.ts` for the stored shape and its lookup function). Match by `source` + `path`. A missing entry gives `uses: 0, hits: 0` (Review Focus 3).
- **`container`:** for API paths, the intercepted request's URL the path came from if the certificate or stats record it. Otherwise leave it undefined, and `oneSourceWarning` then treats every API path as one response when the field has more than one path and all of them are `api`.
- **Texts** (exact, Global Constraints):
  - `pathKind`: `api` → "API", `json-ld` → "Page data", `meta` → "Meta", `xpath` → "Page element".
  - `provenText`: no `provenOn` → "all proof pages"; otherwise "product 1", "products 1 and 3", "products 1, 2 and 3".
  - `runStatsText`: 0 uses → "Not needed yet"; otherwise "{hits} of {uses} ({pct} %)".
  - `oneSourceWarning`: "All backups read the same response — if it changes, they fail together", or null.
- **Header link:** "Open in the app" is disabled with its title when `operatorIsMember` is false.
