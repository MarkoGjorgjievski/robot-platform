# Cut-over — delete the old dashboard, with a new ops overview — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@robot/app` covers everything a person needs. Customers can rename a project. Operators get a cross-customer overview and a per-website certificate page. The old dashboard (`packages/dashboard`) and everything that exists only for it are deleted.

**Architecture:**
- **Operator access:** an env allowlist, `OPS_EMAILS`. Signed-in accounts whose email is listed get `ctx.isOperator`. An `opsProcedure` guards a new `ops` tRPC router, and the app shows an "Ops" sidebar item and `/ops/*` routes only to them.
- **The ops pages read existing data only:** sources, verification currency, drift, runs, costs, the certified paths, and the domain store's per-path hit/miss stats. They change nothing.
- **Deletion:**
  - the dashboard package;
  - its scripts and its `:3456` CORS origin;
  - the session-less `DEFAULT_ORG_SLUG` shim;
  - every tRPC procedure only it used;
  - the already-dead `scraper.*` procedures.

**Tech Stack:** tRPC v11 + zod, Drizzle (no migration), TanStack Start/Router/Query, Tailwind tokens, vitest, pnpm workspaces.

## Global Constraints

- **Operators:**
  - `OPS_EMAILS` is a comma-separated list, matched case-insensitively and trimmed. Empty or unset means nobody is an operator.
  - Every `ops.*` procedure throws `FORBIDDEN` for a non-operator, signed in or not.
  - The app never renders the Ops nav item or the `/ops` pages for a non-operator: `/ops*` redirects to `/projects`.
  - Add `OPS_EMAILS=` to `.env.example` with a comment.
- **Ops is read-only.** No mutation exists in `ops.*`.
- **Ops overview `/ops`:** one row per website across all orgs, with these columns:
  - **Customer:** the org name.
  - **Project.**
  - **Website:** name plus host.
  - **Verified:** "{c} of {n} fields", or "Not verified".
  - **Stopped extracting:** the drift count from `driftedFields`, or "—".
  - **Last run:** status and relative time, or "No runs".
  - **Spent this month:** USD from the same source `usage.byProject` uses.

  **Order:** drift first, then a failed last run, then not verified, then the rest by most recent activity. A row links to `/ops/websites/{sourceId}`. Only customer-schema (verified-flow) websites are listed; legacy sources are left out.
- **Ops website page `/ops/websites/$sourceId`:**
  - **Header:** customer, project, website, host, and links. "Open in the app" goes to `/projects/{slug}/sites/{slug}` and works only if the operator is also a member; otherwise the link is shown disabled with the title "Not a member of {org}".
  - **One section per contract field, named with the customer's field name** (never the internal concept). Each section lists the field's certified paths in try order, one row per path, showing:
    - **Kind:** "API", "Page data" (JSON-LD), "Meta" or "Page element" (XPath).
    - **The path itself,** in monospace.
    - **Proven on:** "all proof pages", or "products 1 and 3" when `provenOn` is set.
    - **In runs:** "{hits} of {uses} ({pct} %)" from the domain store's per-path stats. A path with 0 uses reads "Not needed yet" in neutral colour, never "0 %" and never as a problem.
  - **One-source warning:** when every certified path of a field comes from one API response (same `source: 'api'` and the same request) or from one JSON-LD block, a note reads "All backups read the same response — if it changes, they fail together". It is display only.
  - **Drift:** the latest drift check's per-field result, with each field's text as on the Verification tab.
  - **Wording:** no "cache" anywhere on these pages. The store is called "approved paths".
- **Project rename:** a project Settings page at `/projects/$project/settings` with the name inline-editable (the same inline-rename pattern as website Settings), calling `projects.rename`. It is linked from the project sidebar.
- **Deletion — none of these survive:**

### Task 4: Ops website page — the approved paths, readable

**Files:** modify `ops.ts` (`ops.website({ sourceId })`) and its tests; modify `packages/app/src/lib/ops-view.ts` (`pathKind`, `provenText`, `runStatsText`, `oneSourceWarning`) and its test; create `packages/app/src/routes/_app/ops/websites/$sourceId.tsx`.

**Interfaces — Produces:**

```ts
ops.website → {
  sourceId: string; org: {...}; project: {...}; website: {...}; operatorIsMember: boolean;
  fields: Array<{ key: string; name: string; type: string;
    paths: Array<{ source: 'api' | 'json-ld' | 'meta' | 'xpath'; path: string; provenOn?: string[]; uses: number; hits: number; container?: string }>;
  }>;
  drift: { status: string; results: unknown } | null;   // latest drift check, as sources.driftCheck returns it
  proofUrls: string[];
}
```

**Rules:**
- **Paths:** `fields` come from `loadCurrentCertification`'s `paths`, in try order, named with the contract's field names.
- **Stats:** `uses`/`hits` come from the domain store's per-path stats for `(cert.hostname, 'detail', concept)` (read `domain-cache.ts` for the stored shape and its lookup function). Match by `source` + `path`. A missing entry gives `uses: 0, hits: 0` (Review Focus 3).
- **`container`:** for API paths, the intercepted request's URL the path came from if the certificate or stats record it. Otherwise leave it undefined, and `oneSourceWarning` then treats every API path as one response when the field has more than one path and all of them are `api`.
- **Texts** (exact, Global Constraints):
  - `pathKind`: `api` → "API", `json-ld` → "Page data", `meta` → "Meta", `xpath` → "Page element".
  - `provenText`: no `provenOn` → "all proof pages"; otherwise "product 1", "products 1 and 3", "products 1, 2 and 3".
  - `runStatsText`: 0 uses → "Not needed yet"; otherwise "{hits} of {uses} ({pct} %)".
  - `oneSourceWarning`: "All backups read the same response — if it changes, they fail together", or null.
- **Header link:** "Open in the app" is disabled with its title when `operatorIsMember` is false.

- [ ] **Step 1: Write the failing tests:**
  - **API:** a certified website gets its paths with names in try order and its stats; a path with no stats gets 0/0; FORBIDDEN for a non-operator.
  - **App:** every text helper, including the warning for three `api` paths and its absence for an `api` + `json-ld` mix.
- [ ] **Step 2: Run them to see them fail.** **Step 3: Implement.** **Step 4: Run them to see them pass**, plus the gates and `tsc`.
