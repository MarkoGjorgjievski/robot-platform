# v1.1 — Backend Stability Design

**Date:** 2026-05-22
**Roadmap slot:** Track A, v1.1 (Backend Stability).
**Parent:** `docs/roadmap.md` § v1.1.

---

## Problem & scope

The roadmap lists three v1.1 items. Code reality (verified 2026-05-22):

1. **Data quality checks (prices > 0, URLs valid, no HTML in text)** — **already done.** `packages/scraper/src/data-quality.ts` (`validateExtractedData`) implements price validation (negative=error, zero=warning, >1M=error, currency-string parsing), URL validity (http(s) prefix + `new URL()` parse), HTML-tag stripping for strings, plus number/boolean/date coercion and cross-row checks (all-identical, required-missing). It has tests (`data-quality.test.ts`) and is wired into `extract` STEP 5, returning `qualityIssues`. **No work needed — this spec only records it as satisfied and the roadmap is updated to mark it done.**

2. **Crop screenshots to viewport (token savings)** — **partially done, redesigned here.** Capture already clips to `1280×1600` (not full-page). But that single top crop is the reason below-the-fold data (specs tables, UPC, dimensions on Amazon-class PDPs) is invisible to the multimodal selector AI. This spec replaces the single crop with **progressive legible tiles** (Part A).

3. **Click-to-select for row selector — backend** — **not done.** The cache stores per-*field* paths (with a prioritized `human` source) but the listing **`row_xpath`** (repeating-item container) is regenerated by the AI every run and is never cached or human-overridable. This spec adds a **human row-selector override backend** (Part B).

Items 2 and 3 are independent; they share only the v1.1 banner. Implementation can sequence them in either order.

## Part A — Progressive screenshot tiles

### Rationale

Claude downscales any image so its long edge ≤ ~1568px and bills ≈ post-resize area. A full-page grab (e.g. 1280×9000) becomes a ~223×1568 unreadable strip *and* costs more — worst of both. The current single 1280×1600 crop is legible but only sees the top ~1600px. Capturing is free (local Playwright); cost lives only in what we *feed* the AI. So: capture the whole page once, slice into legible tiles, feed the top tile by default, and escalate to lower tiles **only when fields remain unresolved** — paying for lower regions only while *learning* a new page shape (amortized away once selectors are cached).

### Constants (one place, tunable)

- `TILE_HEIGHT = 1536` (px) — under Claude's ~1568px downscale threshold, so each tile stays sharp at width 1280.
- `MAX_TILES = 3` — cap total captured/feedable tiles (~4608px of page coverage). Bounds both capture work and worst-case AI image cost.

### Capture (`packages/browser`)

- `PageCapture` (`types.ts`) gains `screenshotTiles: Buffer[]`. Invariant: `screenshotTiles[0]` is the existing top crop and `screenshot` continues to equal `screenshotTiles[0]` (backward compatible — every current consumer keeps working).
- In `playwright-browser.ts` capture: after popup dismissal / content expansion, read page height (`document.documentElement.scrollHeight`), compute `tileCount = min(MAX_TILES, ceil(pageHeight / TILE_HEIGHT))` (≥1), and take one `page.screenshot({ clip: { x:0, y:i*TILE_HEIGHT, width:1280, height:TILE_HEIGHT } })` per tile. Set `screenshot = tiles[0]`. The `screenshotFullPage` option is removed (superseded; nothing should request an unreadable full-page image).

### Feed + escalate (`packages/agent` + `packages/api`)

- `agent.generateSelectors(capture, fields, pageType, image?)` and `retrySelectorGeneration(..., image?)` gain an optional `image?: Buffer` that overrides which tile is sent; default remains `capture.screenshot` (tile 0). (Anthropic branch only — Ollama stays text-only.)
- In `extract` STEP 3 (XPath fallback): the first `generateSelectors` pass uses tile 0 (unchanged). After it runs, if schema fields remain unresolved **and** `capture.screenshotTiles.length > 1`, loop over the remaining tiles (`tiles[1..]`, capped by `MAX_TILES`): for each, re-run `generateSelectors(capture, stillMissing, pageType, tile)`, execute the plan, `tryAssign` results (including the existing `ai-vision` fallback). Stop early once `stillMissing` is empty. Each escalation is one multimodal call; the cap bounds it.
- `analyze` (`discoverSchema`) is unchanged — it keeps using tile 0 plus the already-full-page DOM markdown (which carries lower-region text for schema/example proposal). Tiling targets the *visual reverse-search* in `extract`, where seeing the value lets the AI target it.

### Honest limitation (recorded, not solved here)

Lower-region *text* is already in the DOM markdown, so tiles mainly help the visual reverse-search "see" a value to select it — incremental, not a cure-all. Fields genuinely absent from the page (e.g. `upc` on Amazon) won't be helped. A future **DOM-bbox targeted crop** (locate the element, crop to its box) would beat blind tile escalation but is more complex — deferred (see Out of scope).

## Part B — Human row-selector override backend

### Rationale

`row_xpath` defines the repeating-item container on a listing (and the main container on a detail page). It's AI-regenerated every run with no way to pin it, so a mis-detected row boundary on a listing has no human recourse. This adds the **backend** for a human-pinned row selector (the click-to-select *UI* is v2.1; this is the persistence + apply half it will call).

### Storage (`packages/db`)

- Add a nullable `rowSelector` jsonb column to `domain_intelligence` (keyed per existing `(domain, pageType)` row):
  ```
  rowSelector: { xpath: string; source: 'human'; setAt: string } | null
  ```
  Only human-set values are stored here (v1.1 scope). A Drizzle migration adds the column (nullable, default null — no backfill needed). Mirrors the existing nullable jsonb config columns (`paginationConfig`).

### Apply (`packages/scraper` + `packages/api`)

- `lookupDomainCache` / the `DomainCache` type surface `rowSelector` alongside `fieldPaths`.
- In `extract`, after `generateSelectors` returns `plan` and before `buildExtractionScript(plan)`: if `cache.rowSelector` exists, override `plan.row_xpath = cache.rowSelector.xpath`. Human selection wins over the AI's guess (consistent with `human` field-path priority). Applies on both first pass and escalation passes.

### Set (`packages/api`)

- A `scraper.setRowSelector` mutation: input `{ domain, pageType, rowXpath }`. Upserts the `(domain, pageType)` `domain_intelligence` row's `rowSelector` to `{ xpath: rowXpath, source: 'human', setAt: <now> }`. This is the endpoint the v2.1 click-to-select UI will call; in v1.1 it's callable + unit-tested (no UI yet).

### Not included (v1.1)

- Caching the *AI's* `row_xpath` for stability across runs (separate idea; v1.1 is the human-override backend only).

## Out of scope (deferred)

- **DOM-bbox targeted crop** for screenshots (precise per-field cropping) — future refinement if tile-escalation proves wasteful.
- **Click-to-select UI** (visual element picker, the row-pin interaction) — v2.1 dashboard.
- **Caching AI-generated `row_xpath`** — separate follow-up.
- **Surfacing `qualityIssues` in the dashboard** — the checks run and are returned; rendering them is a dashboard concern, not this backend phase.

---

## Testing

- **Part A:** unit-test the tiling math (page height → tile count, capped at `MAX_TILES`, each clip's `y`/`height`) as a pure helper extracted from the capture path. The escalation loop in `extract` is integration-level (verified by dogfooding an Amazon PDP: confirm a lower-tile escalation resolves a below-fold field that tile 0 missed, and that a fully-resolved page makes zero escalation calls).
- **Part B:** unit-test `setRowSelector` (upsert writes the jsonb) and that `lookupDomainCache` surfaces it; assert `extract` overrides `plan.row_xpath` when a human `rowSelector` is present (test the override point as a small pure helper, or via a seeded cache row).
- Workspace: `pnpm --filter @robot/scraper test`, `pnpm --filter @robot/api test`, and `tsc --noEmit` across touched packages green.

---

## Success criteria

- A below-the-fold field that the top tile can't show gets resolved via a capped lower-tile escalation; a page resolved from tile 0 triggers no extra image calls.
- Screenshots fed to the AI stay ≤ `TILE_HEIGHT` tall (legible, no silent downscale); no full-page images are sent.
- A human-set `rowSelector` persists per `(domain, pageType)` and overrides the AI's `row_xpath` in `extract`.
- Data-quality checks remain green (already done); roadmap v1.1 updated to reflect item 1 done, items 2–3 delivered.
