# v1.5 Phase 5 — Global DomainIntelligence Views

**Date:** 2026-05-20
**Parent spec:** `docs/superpowers/specs/2026-05-13-dashboard-architecture-redesign-design.md` (§ Phase 5)
**Roadmap slot:** Track B, v1.5 Phase 5 (the last v1.5 phase; Phases 0–4 done).

---

## Problem

v1.5 Phases 0–4 built the Sandbox→Graduate flow and the project/dataset/source/per-project-domain views. The two **global** domain routes are still `Placeholder` stubs:

- `/domains` — global domain library
- `/domains/{domain}` — DomainIntelligence detail (the shared, cross-customer "moat")

Nothing in the UI currently shows the **per-field cached selectors** (`domainIntelligence.fieldPaths`) — the path each field resolves through, with hit/miss stats and last value. That's the core asset of the system and exactly what an operator needs to diagnose a bad cached path (e.g. the v1.1b dogfood found `diet_type` / `product_description` resolving to the product title via stale `xpath-cached` paths). Phase 5 exposes this, read-only.

## Scope & locked decisions

- **Build only the two global views.** The per-project domain views (`/p/{project}/domains`, `/p/{project}/domains/{domain}`) already exist (Phase 3) and are left untouched.
- **Read-only.** No edits to the cache. "Fixing" (selector override / click-to-select) stays in v2.1. This honors the parent spec's locked decision: *the redesign exposes DomainIntelligence but does not change how it's built or scored.*
- **Driven by `domainIntelligence`, not the `domains` identity table.** The global views are about the cache (the moat), so they read `domainIntelligence` directly. The existing `domains.list` / `domains.getById` (identity table, by uuid, used elsewhere) are not modified.

## Architecture

Follow the established SPA pattern: a TanStack route component issues a tRPC query and renders with the shared `Spinner` / `ErrorBanner` / `EmptyState` / `NotFound` page-states, `Stat` cards, Tailwind light mode, `lucide-react` icons.

### Data layer — two new `domainsRouter` procedures

`packages/api/src/routers/domains.ts`:

1. **`intelligenceList`** — `query()`, no input. Reads all `domainIntelligence` rows, aggregates by `domain`:
   ```
   { domain, pageTypes: string[], totalRuns, successfulRuns, successRate, fieldCount, lastVerifiedAt }
   ```
   - `totalRuns` / `successfulRuns` summed across the domain's pageType rows.
   - `successRate` = `successfulRuns / totalRuns` (0 when `totalRuns === 0`).
   - `fieldCount` = number of distinct field names across the domain's `fieldPaths`.
   - Sorted by `lastVerifiedAt` descending (most recently active first).

2. **`intelligenceDetail`** — `query({ domain: string })`. Returns:
   ```
   {
     domain,
     pageTypes: Array<{
       pageType, totalRuns, successfulRuns, successRate, lastUsedAt, lastVerifiedAt,
       hasJsonLd, hasNextData, apiEndpoints,
       selectors: Array<{ field, source, hits, misses, hitRate, lastValue, lastUsedAt }>
     }>,
     sources: Array<{ id, slug, name, urlTemplate, projectSlug, projectName, datasetName }>  // across ALL projects
   }
   ```
   - `selectors` is `fieldPaths` flattened: one row per (field, path). `hitRate = hits / (hits + misses)` (0 when no uses). A field with `paths: []` still appears once with empty/`—` selector columns (so "discovered-but-never-resolved" fields are visible).
   - `sources` is the cross-customer list: every non-sandbox source whose `urlTemplate` host matches `domain` (same `split_part(urlTemplate,'/',3)` matching used by `detailByProject`, but **not** filtered to one project), joined to project/dataset for context.

Both procedures return plain serializable shapes (the dashboard reads them via tRPC). No mutations.

### `/domains` library — `domains-list.tsx`

Replace the `Placeholder`. A table from `intelligenceList`:

| Domain | Page types | Runs (success/total) | Success rate | Fields | Last verified |

- Each row links to `/domains/{domain}`.
- `EmptyState` when the list is empty ("No domain intelligence cached yet — run an extraction to start building the cache").
- Breadcrumb + header consistent with sibling list views.

### `/domains/{domain}` detail — `domain-detail.tsx` (layout B)

Replace the `Placeholder`. From `intelligenceDetail`:

1. Breadcrumb (`Domains / {domain}`) + header with `Globe` icon and the domain.
2. **Page-type tabs** — one tab per `pageType` (most domains have just `detail` or `listing`; render a single section without tabs when there's only one).
3. Per page type: summary `Stat` cards — total runs, successful, success rate, last verified — plus small JSON-LD / NextData boolean badges.
4. **Flat selectors table**, default-sorted by `hitRate` ascending (failing paths surface first), client-sortable by column. Columns: `field · source · hit-rate · hits/miss · last value · last used`. Rows with a low hit-rate get a subtle warning tint; `paths: []` fields render greyed with `—`.
5. **Sources across customers** — list of `sources` with project/dataset, each linking to `/p/{projectSlug}/sources/{slug}`. `EmptyState` if none.
6. `NotFound` when `intelligenceDetail` finds no rows for the domain.

## Known caveat (surfaced, not fixed)

`domainIntelligence.domain` is stored inconsistently — `extract` saves the full hostname (`www.amazon.com`) while other paths strip `www.`. A domain may therefore have split intelligence rows under `amazon.com` and `www.amazon.com`. Phase 5 displays whatever is stored, grouped by the stored string. Normalizing the cache key is a separate cache-hygiene fix; it will be recorded in `docs/ideas.md` and is out of scope here.

## Testing

- Unit-test `intelligenceList` and `intelligenceDetail` against seeded `domainIntelligence` rows (+ a couple of sources), in the style of `domains.test.ts`: assert aggregation math (summed runs, success rate, field count), selector flattening (hit-rate, empty-path fields included), and the cross-project source join.
- The views are verified by dogfooding against the real Amazon / Nike cache rows already in the DB.

## Out of scope (deferred)

- Any cache edits / selector overrides (v2.1 click-to-select).
- Normalizing the `www.` cache-key inconsistency (cache-hygiene follow-up → `ideas.md`).
- Pagination-pattern / popup-recipe display (not yet in the schema; arrives with v2).
- Changes to the per-project domain views.

## Success criteria

- `/domains` lists every domain with cached intelligence, newest-active first, linking to detail.
- `/domains/{domain}` shows the per-field cached selectors with hit/miss + last value, failing paths surfaced by the default sort, plus cross-customer sources — all read-only.
- New router procedures unit-tested; `pnpm --filter @robot/api test` + dashboard typecheck green.
